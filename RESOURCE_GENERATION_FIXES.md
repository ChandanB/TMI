# Resource Generation Fixes

## Issues Fixed

### 1. ✅ Improved AI Prompt for Better Resource Generation

**Problem:** AI was generating duplicate articles and hallucinating non-existent URLs

**Solution:** Updated the prompt with:
- Explicit instructions to generate 3 DIFFERENT resources
- Clear type requirements (must have one article, one video, one interactive)
- Restricted URLs to main domain URLs only (to avoid dead pages)
- Emphasized uniqueness of each resource

**File:** `TMI/Services/AI/ResourceGenerationService.swift:95-131`

**New Prompt Features:**
```swift
- IMPORTANT: Each resource must be completely different
- REQUIRED MIX (must have one of each):
  1. FIRST resource: type MUST be "article"
  2. SECOND resource: type MUST be "video"
  3. THIRD resource: type MUST be "interactiveContent"
- For URLs, use only the main website URL (not specific pages)
```

## Known Limitations

### URL Accuracy
The AI model generates resource recommendations but **cannot verify URL validity**. The prompt now restricts URLs to main domain pages to minimize dead links, but specific resource recommendations are still generated by the AI.

**Workaround Options:**
1. Use main domain URLs as implemented (reduces but doesn't eliminate dead links)
2. Future: Add manual URL verification/editing in "Add Resource" flow
3. Future: Integrate with a real educational resource API for verified URLs

### Resource Caching (Global)
Resources are cached globally per interest in Firestore (not per user). This means:
- First user to add an interest generates resources for ALL users
- Subsequent users get instant access to cached resources
- More efficient and consistent across all users

To regenerate with improved prompt:
- Delete the interest from the plan and re-add
- Or manually delete from Firestore root: `generatedResources/{interestId}`
